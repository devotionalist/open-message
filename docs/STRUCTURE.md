# 文档组织规则（层层递进）

**权威入口**：[README.md](./README.md)。  
本文只规定**怎么放、怎么读、怎么改**；具体内容在各层正文。

---

## 1. 分层模型（必须遵守）

```text
L0  入口与规则     你在哪、按什么顺序读、改文规则
L1  硬约束与目标   不可违反的合同（先于一切机制）
L2  架构总览       系统长什么样、角色/流程/规格地图
L3  领域细章       按域拆开的可实现设计（机制正文）
L4  工程门禁       审计/开发/测试/运维/客户/生产级标准
L5  说明           运维手册、用户文档、部署说明
```

**递进规则**：

1. 下层不得否定上层（L3 机制不得违反 L1 硬约束）。  
2. 阅读默认 **L0→L1→L2→按需 L3→L4→L5**；禁止从 L5 runbook 反推架构不变量。  
3. 新增文档必须声明所属层，并挂到 [README.md](./README.md) 对应层表。  
4. **不改编号搬迁文件**除非同步全库链接；优先用本层目录组织导航。  
5. 聊天结论必须落入对应层正文；聊天不是权威。  
6. **不入库过程产物**：实现计划、角色手册、握手副本、压测/演练原始输出等。需要留档时用 issue / 本地 `tmp/ops-records/`（gitignore）。

## 2. 目录落位

| 路径 | 层 | 放什么 |
|---|---|---|
| `docs/README.md` | L0 | **唯一总入口**与分层导航 |

| `docs/design/01`–`27` | L3 | 领域细章（按域，见 design/README） |

`docs/design/README.md` = **L1–L4 在 design/ 内的分层目录**（不是第二入口抢戏；总入口仍是 `docs/README.md`）。

## 3. 改文检查单

```text
[ ] 属于哪一层？README 该层表是否已挂
[ ] 是否与更上层冲突？冲突则先改上层或明确优先级
[ ] L3 新能力：13 流程挂号？35 角色？37 合理性？29 问题行？
[ ] L4/L5：是否越级发明 L1/L2 不变量？→ 禁止，开设计缺口
[ ] 是否过程产物（计划/一次性记录）？→ 不进 docs，改设计正文或本地 tmp
[ ] 生产级/握手是否需更新（36）
```
